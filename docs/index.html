The Zero-Middleware Advantage

Traditional CDC stacks require high operational overhead and multi-hop latency. Kinetic collapses the pipe directly into the engine.

The Status Quo

Debezium + Kafka + Connect

Multiple distributed systems, ZooKeeper/KRaft, Java garbage collection pauses, and multi-hop serialization.

4 - 16 GB Memory
5 - 30s Latency
$1,500+/mo Baseline Cost
Postgres ➔ Debezium ➔ Kafka Connect ➔ Kafka Brokers ➔ Iceberg Sink ➔ S3
The Kinetic Way

Single Rust Binary

Streams binary changes directly into contiguous Arrow memory and commits byte-aligned Parquet chunks immediately.

~50 MB Memory
< 500ms Latency
$5/mo Baseline Cost
Postgres / MySQL / Mongo ➔ Kinetic (In-Memory Arrow) ➔ S3 / Iceberg

Engineered for Modern Lakehouses

Everything you need for enterprise change data capture, built directly into the core.

🔌

Multi-Source CDC

Connect natively to PostgreSQL (pgoutput), MySQL (Binlog RBR), and MongoDB (Change Streams) with automatic schema translation.

🏹

Zero-Copy Arrow Buffering

Tuple records are parsed straight into native Apache Arrow columnar vectors in-memory without JSON serialization overhead.

📦

Byte-Aligned Parquet

Directly encodes compressed Snappy Parquet files and streams them into AWS S3, MinIO, or Cloudflare R2 object storage.

🧊

Atomic Iceberg REST Commits

Generates Iceberg DataFile metadata and performs atomic snapshot commits to Unity Catalog, Snowflake Horizon, or Tabulario.

🛡️

Schema Drift Protection

Gracefully adapts to upstream table alterations by soft-logging differences and appending nulls without dropping in-flight data.

📈

Native OpenTelemetry

Embedded Prometheus endpoint on :9090/metrics tracking replication lag, throughput rates, and Iceberg commit latencies.

Quickstart by Database

Select your database source to view the exact setup and launch command.

quickstart-postgres.sh
# 1. Start local cluster (Postgres 16, Iceberg REST, MinIO)
$ docker compose up -d
# 2. Seed test table and publication
$ docker compose exec -T postgres psql -U admin -d kinetic_db < scripts/setup_test_db.sql
# 3. Launch Kinetic with PostgreSQL CDC
$ cargo run -- --cdc-source postgres --pg-url postgres://admin:password@localhost:5432/kinetic_db
quickstart-mysql.sh
# 1. Ensure MySQL has binary logging enabled (binlog_format=ROW)
$ mysql -u admin -p -e "SHOW VARIABLES LIKE 'binlog_format';"
# 2. Launch Kinetic with MySQL Binlog CDC
$ cargo run -- --cdc-source mysql --mysql-url mysql://admin:password@localhost:3306/
quickstart-mongo.sh
# 1. Ensure MongoDB is running as a Replica Set
$ mongosh --eval "rs.status().ok"
# 2. Launch Kinetic with MongoDB Change Streams
$ cargo run -- --cdc-source mongo --mongo-uri mongodb://localhost:27017/?replicaSet=rs0 --mongo-db kinetic_db

CLI & Configuration Reference

Configure Kinetic via command-line arguments or environment variables.

CLI Flag Environment Variable Default Description
--cdc-source CDC_SOURCE postgres Source engine (postgres, mysql, mongo)
--pg-url PG_URL postgres://...:5432/kinetic_db PostgreSQL connection URL
--mysql-url MYSQL_URL mysql://...:3306/ MySQL server connection URL
--mongo-uri MONGO_URI mongodb://...:27017/?replicaSet=rs0 MongoDB connection URI with replica set
--max-batch-size MAX_BATCH_SIZE 5000 Record count threshold triggering Parquet flush
--max-batch-timeout-ms MAX_BATCH_TIMEOUT_MS 500 Timeout threshold in ms for sub-second commits
--iceberg-rest-url ICEBERG_REST_URL http://localhost:8181 Apache Iceberg REST Catalog endpoint
--s3-bucket S3_BUCKET warehouse Target S3 / MinIO storage bucket name
--metrics-addr METRICS_ADDR 0.0.0.0:9090 Prometheus OpenTelemetry metrics HTTP listener
